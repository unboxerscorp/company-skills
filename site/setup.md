# Company Skills 설치

직원 페이지: https://unboxerscorp.github.io/company-skills/

Company Skills 스킬 하나를 설치하고 사용하는 회사 작업마다 공용 목록을 확인한다. GitHub 계정은 필요 없다. 개인 스킬과 기존 인증·설정은 보존한다.

## Codex · Claude Code

1. https://unboxerscorp.github.io/company-skills/download/company-skills.zip 을 내려받고 company-skills 폴더를 Codex의 사용자 .agents/skills 또는 Claude Code의 사용자 .claude/skills에 설치한다. 같은 이름의 개인 설치가 있으면 덮어쓰지 않는다.
2. 설치된 SKILL.md를 읽고 포함된 scripts/sync.py를 해당 도구 옵션으로 실행한다. Python이 없으면 사용 가능한 설치 방법을 안내하고 직접 설치가 가능한 경우 진행한다. Git·Node는 필요 없다.
3. 새 스킬 추가, 수정, 관리하던 스킬 제거, 반복 실행 시 변경 없음이 확인된 항목만 보고한다. 새 채팅이 필요하면 안내한다.

## ChatGPT · Claude

앱이 제공하는 스킬·플러그인 설치 화면에서 Company Skills를 등록한다. Claude의 ZIP 업로드는 위 다운로드를 사용한다. ChatGPT에서 해당 설치 기능이 제공되지 않으면 SKILL.md를 읽어 현재 채팅에 적용하고 앱에서 가능한 지속 설정만 안내한다. 연결된 브라우저·데스크탑 조작 권한이 없으면 직접 필요한 단계만 설명한다. 설치·제거를 자동화할 수 없는 상태를 완료로 보고하지 않는다.

로컬 파일을 바꿀 수 없는 앱은 목록과 최신 SKILL.md를 작업마다 읽어 적용한다. 목록에서 빠진 업무 스킬은 적용하지 않는다. 실제 앱에 업로드된 개별 스킬 제거는 앱에서 조작이 필요할 수 있다.

## Grove

Grove 운영자가 이 절차를 요청한 실행 환경에만 적용한다. 실행 에이전트가 Codex 또는 Claude Code이면 해당 로컬 절차를 따른다. Company Brain 연결은 서비스 계정을 사용한다. 직원 개인 인증을 요구하지 않는다.

## Company Brain 연결

회사 기억 기능을 사용하려면 https://base-inbrain-develop.taile4260.ts.net/company-brain/setup 의 해당 앱 인증 절차를 따른다. 기존 연결이 정상이라면 재설정하지 않는다. 회사 Google 로그인과 필수 승인은 사용자가 진행한다. 전 직원에게 공식 공유 가능한 내용만 기록하며 민감 정보와 그 요약은 제외한다.

## 자동 반영의 범위

Company Skills 스킬을 사용할 때 동기화한다. 백그라운드 실행을 의미하지 않는다. 이 도구가 관리하지 않는 설치나 사용자가 수정한 파일은 보존한다. 목록·파일 검증이 실패하면 설치와 제거를 하지 않는다. 훅과 인증 설정은 자동 동기화 대상이 아니다.

## 업무 기록까지 적용

Company Skills와 MCP 설치 후 위 스킬의 완료 절차를 수행한다. 회사 작업에 적용되는 중앙 지침과 작업 공간의 AGENTS.md·CLAUDE.md 또는 앱의 지속 지침에 다음 규칙을 기존 내용을 보존하며 반영한다. 회사 범위 밖 개인 설정은 바꾸지 않는다.

> 명확한 회사 업무에서는 Company Skills로 최신 스킬을 확인하고 Company Brain으로 시작 시 관련 맥락을 조회한다. 중요한 변경과 최종 답변 전에는 전 직원에게 공식 공유 가능한 목적·실행 내용·수정·검증 결과·남은 일을 저장한다. 민감 정보와 이를 유추할 수 있는 요약은 제외하고 불명확하면 저장을 생략한다. 저장 후 같은 기록을 재조회해 실제 작업과 결과가 일치하는지 확인한다. 업무 완료와 기록 실패는 구분한다.

Grove에서는 중앙 지침뿐 아니라 각 실제 실행 노드로 설정·지침이 전달되는 경로와 기존 세션의 도구 노출을 확인한다. 전체 대상 / 확인된 적용 / 기존 세션 미반영 / 다음 작업 반영 예정 수를 실제 근거로 보고한다. 공용 설정 준비와 실행 세션 반영을 구분하며 진행 중인 작업을 중단하거나 강제 재시작하지 않는다. 새 작업 또는 안전한 작업 경계에서 반영한다. 다른 노드까지 접근 권한이 없으면 그 범위만 미확인으로 남긴다.

검증은 이미 요청받은 실제 회사 작업 한 건의 수행 결과를 안전하게 기록하고 별도로 다시 읽어 작업 식별자·변경·검증 결과를 대조한다. whoami와 설치 테스트 저장만으로 검증 완료라고 하지 않는다. 실제 작업이 없으면 설치 검증과 실제 업무 기록 미검증을 구분한다.

최종 보고: 연결 / 업무 지침 / 노드·세션 반영 / 실제 업무 기록 검증을 각각 근거와 함께 구분한다. 누락 항목이 있으면 전체 완료라고 보고하지 않는다.

## 선택: 과거 회사 업무 가져오기

최초 설치 후 과거 업무를 가져올지 안내한다. 자동 전체 수집은 기본값이 아니다. 사용자가 이미 허용한 회사 범위가 있으면 그 범위 안에서 진행하고, 없으면 앱·회사 작업 공간·기간 등 필요한 범위를 한 번에 확인한다. 범위 확인 전에는 과거 대화를 읽거나 업로드하지 않는다. 설치·서비스 계정 등록만으로 다른 직원의 과거 세션 수집을 허용하지 않는다.

허용되면 최신 company-history-import 스킬을 읽고 앱의 대화 조회 기능이나 사용자가 지정한 내보내기를 사용한다. 개인·민감 정보를 업로드 전에 제외하고 전 직원에게 공식 공유 가능한 업무 결정·행동·수정·검증·남은 일만 요약한다. 원문 전체나 분류를 위한 원본을 회사 서버로 먼저 보내지 않는다. 민감한 사실이 유추되는 요약도 제외한다.

원래 날짜·출처와 가져온 날짜를 분리하고 안정된 출처 식별자 해시·요약 해시로 중복을 방지한다. 장기 가져오기는 비공개 로컬 처리 상태를 남겨 중단 후 재개한다. 저장 후 재조회로 요약·출처 날짜·해시를 확인한다. 가져온 범위, 저장·중복·제외·실패 집계와 미접근 범위를 보고한다. 앱에서 과거 조회를 지원하지 않으면 내보내기 등 실제 가능한 방법만 안내한다. 과거 업무 사실의 검증 여부와 가져오기 성공은 구분한다.
